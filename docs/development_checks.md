## Timing and counter interpretation

- `setup` includes fixture initialization and history construction. Nested
  `target_verification` records identify real verification separately; do not add
  them to setup. Interpreter/import startup is outside these child phase timers
  and remains visible in enclosing elapsed time.
- `bookkeeping` covers the production operation and replay. Its `provider_seconds`
  counter measures actual fake adapter body time; subtract that inclusive body
  time when reporting runner-only elapsed. Target verification is already outside
  this phase. `opposite_consumer` is separately timed and is not runner latency.
- `git` counts calls through `gitws._git`; `managed_git` counts its imported
  managed process boundary, including direct blob/diff helpers. These overlap and
  must not be summed. Other `procs.run_process` calls have a separate counter.
  Pinned/manual subprocess internals are outside this interpreter's counters.
- Pending guards, workspace scans, history/reference validation, reference reads,
  report reads and report parses count actual forwarded calls, including repeats.
  Their durations are inclusive and overlap. SHA256 bytes count bytes actually
  supplied to constructors/updates, including repeated hashing and non-evidence
  inputs. Path read bytes count explicit `Path.open().read()` results: raw binary
  lengths or UTF-8 lengths of decoded text. They are not unique evidence size,
  physical disk traffic or a complete count of child-process reads.
- Phase CPU is this Python process's CPU. Elapsed includes waiting; subtracting
  CPU does not isolate Git CPU or operating-system scheduling. Profiles are
  diagnostic only and their nested cumulative times must not be added.
- Inventory records bind actual pre-operation event/reference/listed-file/byte
  counts. Preservation records compare original evidence bytes and pre/post
  workspace witnesses. Routed mutation legitimately changes HEAD and ledger;
  idle requires identical witnesses. Root candidate and retained raw identities
  are compared before and after the batch.
