## Selection and consumers

`render.resumes_contract` reverse-scans validated history. An exact-slice resolved
event preserves the last issued task only until the next exact-slice prompt.
Other scopes and neutral events cannot grant continuation. `coding_envelope`
uses the admitted roadmap otherwise; previews do not append or consume authority.
`task_contract` selects before issuance and reads the bound envelope afterwards.
Missing or altered selected evidence fails validation without roadmap fallback.

Every field travels in the canonical envelope and both prompt renderers:

| Fields | Additional F consumer |
| --- | --- |
| title, objective, acceptance, non_goals, read_first | Task instructions; no independent execution |
| allowed_prefixes, forbidden | Actual coding drift/fence checks; cumulative manifest retains unchanged older identities |
| focused | Rendered focused instructions; not an extra runner invocation |
| full | Pre-probe executable admission and real native verification argv |
| runtime | Pre-probe, coder, verifier and review identity via `receipt.native_runtime` |
| timeout_seconds | Verification and operation reservation, clipped by configuration and durable remaining allowance |
| observation | Native verification execution and receipt |
| notes, memory | Frozen instructions; no additional memory execution |

Review and retry bindings retain roadmap, product, Git, seat, prompt, issued
references and runtime identity. A later legal roadmap change does not substitute
the issued task, but also does not authorize reuse of an older checkpoint binding.
Historical blockers and resolutions remain source-bound context in a new ordinary
prompt; they do not impose the previous coder dispatch policy. Immediate resumed
coder blockers retain that policy check. Old artifacts are never rewritten.
